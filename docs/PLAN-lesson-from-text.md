## 1. 한 문장

**영어 교사가 다음 시간에 쓸 지문을 붙여 넣으면, 그 글이 어떤 종류의 글인지 판정하고,
그 종류에 맞는 45분 수업 계획 · 교실 활동 3~5개 · 혼자 할 수 있는 숙제를 뽑아 준다.**

유형이 활동을 정한다. 이야기글과 논증글에 같은 활동을 주면 안 된다는 것이 이 앱의 전부다.

## 3. 유형 축 설계 — 두 축을 겹쳐 쓴다

### 축 A · 교육과정이 쓰는 이름 (교사가 보는 것)

설명문 · 논설문 · 이야기글 · 안내문 · 실용문(광고·이메일·편지·공지) · 도표/그래프 · 대화문 · 시·노래

역할: 교사에게 익숙한 말로 알려 주고, 성취기준을 붙이는 고리.

출처: 2022 개정 영어과 교육과정 고시의 '담화와 글의 유형'.
**M0 에서 고시 원문을 읽어 목록을 확정하고, `Korea-curri-standards-db` 의 빈 `text_type` 을 채워 정본으로 만든다.**
단, 성취기준 행마다 유형을 박아 넣지 않는다. 유형 목록을 별도 표로 만들고 성취기준↔유형을 다대다로 잇는다.
고시에 성취기준별 유형 근거가 없으므로, 없는 근거를 지어 붙이지 않는다.

### 축 B · 글이 생각을 펼치는 방식 (엔진이 쓰는 것)

`aku` 에 이미 있는 8종을 그대로 쓴다. 443편에 이미 붙어 있어 시작부터 예시가 있다.

| slug | 이름 | 뜻 |
|---|---|---|
| `explanation` | 설명 | 개념을 직접 풀어 설명한다 |
| `example` | 사례 | 구체적 사례로 일반 원리를 보인다 |
| `experiment` | 실험/연구 | 연구 절차와 결과로 주장을 지지한다 |
| `analogy` | 비유 | 다른 영역에 빗대어 이해시킨다 |
| `historical_case` | 역사적 사례 | 시간 순의 실제 사례를 든다 |
| `argument` | 논증 | 통념을 반박하며 주장을 세운다 |
| `narrative` | 서사 | 인물과 사건의 흐름으로 전개한다 |
| `description` | 기술/안내 | 사실·절차·정보를 전달한다 (실용문 포함) |

역할: **활동을 고르는 열쇠는 이 축이다.** 활동 레시피마다 "어떤 전개 방식에 붙는가"를 적어 둔다.

### 두 축을 겹치는 이유

축 A 만 쓰면 "설명문입니다" 까지만 알려 주고 활동은 결국 AI 가 매번 새로 지어내 들쭉날쭉해진다.
축 B 만 쓰면 교사에게 낯선 말이 되고 성취기준 연결 근거가 약해진다.
그래서 **화면에는 축 A 를 쓰고, 활동 선택은 축 B 로 한다.**

### 반드시 지킬 금지 사항 (AKU 실측 근거)

`aku/docs/USAGE.md` 가 기록한 실측: 전개 방식과 난이도의 큰 상관 0.599 는 **집단 간 착시**이고,
집단 안에서는 **0.071** 이다. 그래서 이 앱은 절대 이렇게 말하지 않는다.

> ✗ "논증문이라 어렵습니다"

말할 수 있는 것은 이 둘뿐이다.

> ✓ "이 글은 실용문이 아니라 논증문입니다" (종류)
> ✓ "이 글의 Lexile 은 980 인데 중2 상한은 720 입니다" (난이도 — grade-bounds 로 따로 잰다)

## 4. 파이프라인 (4단계)

```text
[지문 붙여넣기 + 학년]
        │
  ① 재는 단계 (AI 없음, 결정론)
        │   낱말수 · 문장수 · 문장당 낱말 · Lexile · FK · 어휘 급수
        │   → grade-bounds 대조 → 학년 적합 / 상한 초과 / 하한 미달
        ↓
  ② 판정 단계 (신호와 AI 가 서로 감시)
        │   결정론 신호 : 인용부호 · 과거시제 비율 · 1인칭 · 명령문 · 수치와 단위 ·
        │                시간 표현 · 역접 연결어(however, but) · 정의문(is a kind of)
        │   AI 판정    : 축 A 1개 + 축 B 1개 + 근거 문장 인용
        │   두 결과가 다르면 → 교사에게 되묻는다 ("이 글은 a 논증문 / b 설명문 중 무엇입니까")
        ↓
  ③ 고르는 단계 (AI 없음, 원장 조회)
        │   활동 레시피 원장에서 (축 B × 학년 × 기능 × 차시분량) 으로 후보를 거른다
        │   seed 고정 → 같은 지문 · 같은 학년이면 같은 세트가 나온다
        ↓
  ④ 채우는 단계 (AI)
            레시피의 빈칸(slot)만 이 지문의 내용으로 채운다
            레시피 자체는 AI 가 만들지 않는다
        ↓
[지도안 + 활동 3~5 + 숙제 1~2] → 학생 활동지 / 교사 지도안 각각 인쇄
```

**③과 ④를 나눈 이유.** 활동 전체를 AI 에게 시키면 매번 그럴듯하지만 매번 다른 글이 나오고,
같은 지문을 두 번 넣으면 다른 수업이 나온다. 교사가 믿고 쓸 수 없다.
원장에서 고르고 빈칸만 채우면 활동의 뼈대는 사람이 검토한 것이고 살만 AI 가 붙인다.
(`English_learning_games` 의 네 축 분리와 같은 구조 — "게임 N × 팩 M" 을 N+M 개 부품으로 유지한 그 방식.)

## 5. 활동 레시피 파일 계약

`content/recipes/<id>.json` 한 파일 = 활동 하나. **코드를 고치지 않고 파일만 더해 활동을 늘린다.**
검증기 `scripts/validate-recipes.mjs` 는 앱 코드를 import 하지 않는다 (의도적으로 — `English_learning_games` 선례).

```jsonc
{
  "id": "narrative-timeline-rebuild",
  "titleKo": "사건 순서 다시 세우기",
  "worksWith": ["narrative", "historical_case"],   // 축 B. 여기가 활동 선택의 열쇠
  "stage": "while",                                 // pre | while | post | home
  "skill": "reading",
  "grades": ["middle1", "middle2", "middle3", "high1"],
  "minutes": 12,
  "grouping": "pair",                               // individual | pair | group | whole
  "materials": ["잘라 쓴 문장 조각"],
  "layer": "structure",                             // activity-inventory 의 13 층위
  "slots": [                                        // AI 가 채우는 자리. 이것 말고는 못 건드린다
    {
      "key": "events", "kind": "sentence_list", "n": 6,
      "from": "passage", "rule": "시간 순서를 담은 문장만. 원문 그대로 옮긴다"
    }
  ],
  "studentText": "아래 {{n}}개 문장을 사건이 일어난 순서대로 놓으세요.",
  "teacherNote": "순서를 정한 근거 문장을 말하게 하면 연결어 학습으로 이어진다.",
  "homeworkVariant": "…"                            // 선택. 숙제로 낼 때의 문장
}
```

**숙제의 추가 조건 두 가지** (`"stage": "home"`)

- 교사 없이 혼자 끝낼 수 있어야 한다 (짝·모둠 활동은 숙제가 못 된다)
- 정답 또는 점검 방법이 함께 나와야 한다 (학생이 스스로 확인할 수 있어야 한다)

**초기 원장 시드.** `activity-inventory` 의 활동 70개와 13 층위 매트릭스를 출발점으로 쓴다.
그중 읽기 수업 한 차시에 실제로 넣을 수 있는 것만 골라 **24~30개**를 M2 에서 만든다.
층위별 최소 1개, 축 B 8종마다 최소 2개를 채우는 것을 합격선으로 한다.

## 6. 산출물 계약

```jsonc
{
  "passage": { "hash": "sha256…", "words": 172, "sentences": 9, "lexile": 980 },

  "fit": { "grade": "middle2", "verdict": "over",          // ok | over | under
           "reasons": ["Lexile 980 > 중2 상한 720", "문장당 최대 낱말 26 > 18"] },

  "type": { "curriculum": "논설문", "development": "argument",
            "confidence": "high",                          // high | ask (ask = 교사에게 되물음)
            "evidence": ["However, this belief is mistaken.", "…"] },

  "standards": [ { "id": "[9영03-05]", "text_ko": "…원문 그대로…",
                   "domain": "읽기", "verified": true } ],

  "plan": { "duration": "1차시",
            "intro": ["recipeId…"], "main": ["recipeId…"], "close": ["recipeId…"] },

  "activities": [ { "recipeId": "…", "minutes": 12, "filled": {} } ],
  "homework":   [ { "recipeId": "…", "filled": {}, "selfCheck": "…" } ]
}
```

성취기준의 `text_ko` 는 **DB 원문 그대로** 넣는다. AI 가 성취기준 문장을 쓰지 않는다.
AI 가 하는 일은 후보 중에서 고르는 것뿐이고, 고른 근거를 함께 남긴다.

## 7. 검증 계획 — 만들기 전에 재는 것부터

`rubric-maker-v2` 의 S0 킬 실험과 같은 순서를 따른다. 먼저 "이 일이 되는가"를 재고, 되면 만든다.

### K1 · 유형 판정이 맞는가 (M0, 하루)

- 교사가 실제로 넣을 지문 **30편**을 모은다 (교과서 본문 10 · EBS 10 · 모의고사 10, 중·고 섞어서)
- **사람이 먼저 라벨을 붙인다.** 축 A 1개, 축 B 1개. 이 정답지를 먼저 고정한다
- 그 다음 판정기를 돌려 일치율을 잰다
- **합격선 : 축 B 8종에서 24/30 (80%) 이상.** 못 넘으면 "유형 분석" 간판을 내리고 축을 다시 짠다

> ⚠ AI 가 자기 라벨을 자기가 채점하게 두지 않는다.
> `English_learning_games` 에서 얻은 교훈 — **실패할 수 없는 검사는 검사가 아니다.**
> 그때 공허한 검증이 채점기 버그 두 건을 가렸다.

### K2 · 활동이 유형을 따라 갈리는가 (M2 끝)

같은 학년 · 같은 길이의 서사문 1편과 논증문 1편을 넣는다.
나온 활동 집합이 **절반 이상 달라야** 한다. 같으면 유형 분석이 장식이라는 뜻이므로 원장을 고친다.

### K3 · 교사가 얼마나 고치는가 (M6, 진짜 지표)

본인 수업 2차시에 실제로 써 보고, 인쇄 전에 손댄 곳을 센다.
활동당 수정률이 절반을 넘으면 그 레시피는 원장에서 뺀다.

### 상시 게이트 (CI)

- `validate-recipes.mjs` — 계약을 어긴 레시피는 머지 차단
- 성취기준 인용이 `verified = 1` 행이 아니면 실패
- 학년 적합성 판정은 AI 없이 계산되므로 단위 테스트로 고정

| **M1** | 판정 엔진 + 학년 적합성 게이트 + 성취기준 후보 추출 · `lessons.ts` 모델 경로 수리 | 2~3일 | 지문을 넣으면 ①②가 화면에 뜬다. 성취기준은 verified 만 |
| **M2** | 레시피 원장 24~30개 + 무의존 검증기 + K2 | 2~3일 | 검증기 통과, 축 B 8종마다 2개 이상, K2 통과 |
| **M3** | 조립과 빈칸 채우기 + 학생지/교사지 인쇄 | 2~3일 | 지문 하나로 인쇄물 두 장이 한 번에 나온다 |
| **M4** | lesson-planner 에 '지문' 탭 신설 (기존 '주제' 탭은 그대로 둔다) | 2일 | 기존 기능이 안 깨진다. 자료실에 저장하고 다시 열 수 있다 |
| **M5** | 학생 배정(`assignments.ts`) + 루브릭 축 연결 | 2~3일 | 숙제를 명부 학생에게 배정, 성취수준 축으로 채점표 |
| **M6** | 실사용 2차시 + K3 측정 | — | 수정률 수치가 남는다 |

M0~M4 가 쓸 만한 물건의 최소선이다. M5~M6 은 그 다음.

## 9. 위험과 대응

| 위험 | 왜 실제 위험인가 | 대응 |
|---|---|---|
| **저작권** | 교사가 교과서·EBS 본문을 그대로 붙여 넣는다 | 기본값은 **원문을 서버에 저장하지 않는다.** 해시와 분석 결과만 남긴다. 교사가 '내 자료실에 저장'을 직접 누를 때만 본인 계정 안에 저장한다. 공개 라이브러리에는 어떤 경우에도 올리지 않는다. `copyright-cleansing` 을 붙일지는 M4 에서 판단 |
| **유형이 애매한 글** | 설명과 사례가 섞인 글이 실제로는 대부분이다 | 확신이 낮으면 판정을 숨기고 교사에게 둘을 보여 주고 고르게 한다. 틀린 판정을 자신 있게 말하는 것이 제일 나쁘다 |
| **AI 키** | `models.ts` 주석에 "Anthropic 키가 죽어 Gemini 로 백킹" 이라 적혀 있고 `lessons.ts` 는 그 경로를 안 탄다 | M1 첫 커밋에서 수리하고, 배포본 키가 살아 있는지 실제 호출로 확인한 뒤 진행 |
| **성취기준 오인용** | 고등 표현 `needs_review` 행은 고시문과 다르다 (이슈 #3) | `verified` 만 조회하도록 SQL 층에서 강제하고 테스트로 고정 |
| **레포가 또 하나 늘어남** | 이미 192개 | 새 레포를 만들지 않는다. KES 안에서 한다 |

## 10. 하지 않을 것

- 유형으로 난이도를 말하지 않는다 (AKU 실측이 반박한다)
- AI 가 활동을 자유 창작하게 두지 않는다 (원장에서 고르고 빈칸만 채운다)
- 초등을 먼저 하지 않는다 (지문이 20~60낱말이라 유형 분석이 거의 무의미하다)
- 지문 원문을 공개 저장하지 않는다
- 교사 50명 베타를 잡지 않는다 — 본인 수업에서 먼저 쓴다
